# منصة أ/ إسماعيل عماد التعليمية

منصة تعليمية (من الصف الرابع الابتدائي إلى الثالث الثانوي): إعلانات، دروس YouTube، اختبارات بمحاولة واحدة، منظّم دراسة، مساعد ذكي، ولوحة إدارة.

## المعمارية (بدون Cloudflare وبدون Cloud Functions)

```
المتصفح ──► Firebase Hosting (ملفات ثابتة)
   ├──► Firebase Authentication (الدخول)
   └──► js/backend/*  ──► Cloud Firestore (محمي بـ firestore.rules)
```

- **الطالب** يكتب كودًا من 5 أرقام وكلمة مرور من 6 أرقام. المنصة تحوّل الكود تلقائيًا إلى بريد وهمي `الكود@students.mrismailemad.com` (لا تُرسل له رسائل) وتسجّل الدخول به عبر Firebase Authentication.
- **الأدمن** يدخل ببريده الحقيقي وكلمة مروره، ويلزم وجود مستند `admins/{uid}`.
- حساب دخول الطالب يُنشئه الأدمن مع الكود (صفحة الأكواد أو صفحة رفع الأكواد).
- رقم مستند الكود في `codes` هو **الكود نفسه**، ورقم مستند الطالب في `students` هو **uid** حسابه.
- `firestore.rules` تقفل القاعدة: الطالب لا يرى إلا بياناته، وتعطيل كود يقطع صلاحياته فورًا، والأدمن وحده يرى الأكواد وكلمات المرور.
- مجلد `worker/` هو الـ Worker القديم وغير مستخدم.

## التشغيل لأول مرة (بالترتيب)

1. **Firebase Console ← Authentication ← Sign-in method ←** فعّل **Email/Password**.
2. **Firestore Database:** أنشئ القاعدة (Production mode) إن لم تكن موجودة.
3. انشر (من Google Cloud Shell):
   ```bash
   unzip -o <اسم-الملف>.zip
   cd manasa
   npx firebase-tools login --no-localhost
   npx firebase-tools deploy --only hosting,firestore:rules --project manasty-e422d
   ```
4. افتح `https://mrismailemad.com/setup` فورًا بعد النشر، واكتب بريدك وكلمة مرور قوية، ثم **إنشاء كل الكوليكشنات**. هذا ينشئ حساب الأدمن ويُغلق إنشاء أدمن جديد.
5. **احذف** `setup.html` و`setup.js` من المشروع وأعد النشر.
6. ادخل من `/admin/login`، ثم أنشئ الأكواد (أو ارفعها من `admin/import-codes`).
7. ضع مفتاح الذكاء الاصطناعي في `settings/ai` (حقل `apiKey`).

## ملاحظات مهمة

- **الأكواد الكثيرة:** Firebase قد يوقف إنشاء الحسابات مؤقتًا لكثرة الطلبات. المنصة تُنشئ ما أمكن وتُبلغك، وأعد المحاولة بعد قليل (الأكواد المنشأة لا تتكرر).
- **التصحيح في المتصفح:** إجابات الاختبار داخل مستند الاختبار، فطالب متمرّس يستطيع قراءتها. هذا حد المعمارية بلا خادم.
- **مفتاح الذكاء الاصطناعي** يقرؤه أي طالب مفعّل. استخدم مفتاحًا مقيّدًا بالنطاق وبحصة محدودة من Google.
- لإضافة أدمن ثانٍ لاحقًا: احذف المستند `config/adminLock` من Console مؤقتًا، أو أنشئ مستند `admins/{uid}` يدويًا.
- ملفات JS و CSS تُحدَّث فورًا مع كل نشر (بدون تخزين مؤقت طويل).

## النظام البصري (هوية Editorial Learning)

- **الفكرة:** عالم الطالب المصري اليومي: ورق مربعات، حبر أزرق غامق، قلم المدرس الأحمر، وماركر أصفر.
- **الألوان:** الحبر الأزرق = الهوية والإجراء الأساسي، الأحمر = التصحيح والأخطاء، الأصفر = الإنجاز والعنصر النشط، الأخضر = «صح» والتقدّم فقط.
- **الخطوط:** عناوين بـ Alexandria، ومتن بـ IBM Plex Sans Arabic، وأرقام بـ Inter (تُحمَّل من Google Fonts).
- **الملفات:** `css/tokens.css` (كل القيم) ← `base.css` ← `components.css` (الأزرار والنماذج والبطاقات) ← `layout.css` (الهيدر والتنقل) ← `screens.css` (تصميم الصفحات). كل صفحة تحمّل `screens.css` بعد أنماطها المضمّنة.
- **قاعدة:** أي لون أو حجم جديد يُضاف أولًا كـ token في `tokens.css`، ولا تُكتب قيم ثابتة في الصفحات.

## بنك مستر إسماعيل

- الطالب: `bank.html` (رابط في الشريط السفلي وفي «أدواتك»). الأدمن: `admin/bank.html` (من «وصول سريع»).
- الباك إند: `js/backend/bank.js` و`js/backend/admin-bank.js`. القواعد: آخر قسم في `firestore.rules`.
- **السياسة المالية:** الخصم عند تأكيد الطالب (معاملة Firestore واحدة: طلب + خصم + سجل + مخزون) ← رفض قبل التسليم = استرجاع كامل كمعاملة `refund` + إعادة الكمية ← بعد التسليم لا استرجاع ← رصيد غير كافٍ عند التأكيد = لا خصم + منع 30 يومًا.
- منع التكرار: مفتاح طلب يُولَّد لكل نافذة تأكيد ومعرّفات مستندات ثابتة.
- لا يوجد حذف لأي سجل بنكي (الجوائز تُخفى فقط).
- تهيئة الكوليكشنات: زر «تهيئة كوليكشنات البنك فقط» في `setup.html` (لا يلمس الأدمن ولا الإعدادات ولا أي كوليكشن فيه مستندات).


## الأحداث والألعاب التفاعلية

- الإدارة: `admin/events.html` (من «وصول سريع»). الطالب: `events.html` ← `event.html` ← `event-play.html` (رابط في الرئيسية).
- الكوليكشنات: `events` و`eventParticipations` (المعرّف `{eventId}_{uid}`). القواعد في آخر `firestore.rules`.
- **إضافة لعبة:** ضع ملف HTML في جذر المشروع بجانب `index.html` باسم `game-<اسم>.html` (حروف إنجليزية/أرقام/-/_)، وملفاتها التابعة بأسماء تبدأ بـ `game-` أو داخل مجلد يبدأ بـ `game-`، ثم انشر. أنشئ الحدث واكتب اسم الملف في «اسم ملف اللعبة» (زر «فحص وجود الملف» متاح).
- **العزل:** تعمل اللعبة في iframe بـ `sandbox="allow-scripts allow-pointer-lock"` (بدون same-origin)، وترويسات `firebase.json` لملفات `game-*` تضيف CSP بـ sandbox.
- **النتائج:** لإرسال نتيجة تستدعي اللعبة: `parent.postMessage({source:"mrismail-game", type:"complete", score:80}, "*")`. تُحفظ «قيد المراجعة» ولا تُعتمد إلا من الأدمن.
- **قيد:** ملفات الألعاب ثابتة وعامة؛ من يعرف رابطها يفتحها مباشرة (المنصة تفرض الوقت والمشاركة على التسجيل فقط).

### حدود النظام الفعلية (الأحداث والألعاب)

- **الملفات عامة:** `game-*.html` وتوابعها ثابتة في الاستضافة، ويمكن لأي شخص يعرف الرابط فتحها مباشرة (حتى خارج وقت الحدث). المنصة لا تحمي الملف نفسه؛ كل ما تفرضه هو **الوقت والمشاركة عند التسجيل** (يُنشأ مستند المشاركة فقط أثناء الحدث ولمن يحق له، وتتحقق القواعد من ذلك). لا تضع داخل ملف لعبة أي إجابات أو بيانات سرية.
- **النقاط غير موثوقة:** النتيجة تأتي من كود يعمل في متصفح الطالب، فيمكن تزويرها. لذلك تُحفظ دائمًا كـ«قيد المراجعة» (`reportedScore`) وتُرفض إن تجاوزت الحد الأقصى، ولا تصبح نقاطًا حقيقية (`score`) إلا باعتماد الأدمن من تبويب «المشاركات والنتائج». لا تربط جوائز أو أرصدة بالنتيجة المُبلَّغ عنها مباشرة.
- **ما يفعله صاحب المنصة لإضافة لعبة:**
  1. سمِّ الملف `game-<اسم>.html` في جذر المشروع (حروف إنجليزية وأرقام و`-` و`_` فقط).
  2. ضع التوابع (JS/CSS/صور/JSON/خطوط) في مجلد `game-<اسم>/` بجانبه، وأشر إليها بمسارات تبدأ من الجذر مثل `/game-<اسم>/app.js` (الموقع يستخدم cleanUrls فيُحذف `.html` من الرابط، فالمسارات النسبية مثل `./app.js` تُحلّ من الجذر وقد تنكسر).
  3. لا تعتمد على `localStorage` أو `sessionStorage` أو cookies أو `parent.document`: اللعبة تعمل بأصل مجهول (sandbox) فهذه كلها محجوبة. الاتصال مسموح لنفس الموقع فقط (`connect-src 'self'`).
  4. لإرسال نتيجة: `parent.postMessage({source:"mrismail-game", type:"complete", score:80}, "*")`. وإن لم يكن للحدث نقاط يظهر للطالب زر «أنهيت اللعبة».
  5. انشر (`firebase deploy --only hosting`)، ثم أنشئ الحدث من `admin/events.html` واضغط «فحص وجود الملف» قبل نشره للطلاب.
- **ترويسات `firebase.json`:** وثائق Firebase لا تحدد أولوية الترويسات عند تطابق أكثر من قاعدة على الملف نفسه، لذلك لا نعتمد على الترتيب: القاعدة العامة صارت `!/game-*{,/**}` (لا تنطبق على `game-*`)، وقاعدة `/game-*{,/**}` تحمل كل الترويسات الأمنية مع CSP اللعبة. عند إضافة ترويسة أمنية جديدة للموقع أضفها في **القاعدتين**. بعد أي نشر تحقق: `curl -I https://<موقعك>/game-<اسم>.html` ويجب أن تظهر `sandbox` داخل `Content-Security-Policy`.
- **التهيئة:** من `setup.html` زر «تهيئة كوليكشنات الأحداث فقط» (لا يلمس الأدمن ولا الإعدادات ولا أي كوليكشن فيه مستندات). احذف `setup.html` و`setup.js` بعد الانتهاء كما هو مذكور أعلاه.
- **الاختبارات:** `cd bank-tests && node --import ./register.mjs events.test.mjs` (منطق الباك إند)، و`cd bank-tests/browser && PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers HEADER_MODE=last node browser.test.mjs` (متصفح حقيقي؛ جرّب `first` أيضًا)، و`cd bank-tests/rules && npm i && npm test` (قواعد Firestore على Emulator: يتطلب Java ولم يُنفَّذ في بيئة التطوير).
